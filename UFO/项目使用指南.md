# UFO 项目专属使用指南

本文针对当前工作区中的 UFO² Windows 桌面自动化项目编写，介绍环境安装、模型配置、任务运行、日志查看和常见问题。当前工作区根目录是 `D:\liminghao\pycharm\file\ufo_test\UFO`；下面的新克隆流程会将团队仓库放在 `D:\liminghao\pycharm\file\xixi\ufo-2`。

## 1. 项目做什么

UFO² 接收自然语言任务，由 HostAgent 规划并分派步骤，再由对应应用的 AppAgent 观察桌面、操作窗口并检查进度。它适合在 Windows 桌面上执行跨应用任务，例如打开程序、填写内容、保存文件和核对结果。

这个仓库还包含 UFO³ Galaxy 多设备编排代码。本文主要介绍 UFO² Windows 自动化入口；Galaxy 的独立启动方式见[第 8 节](#8-galaxy-多设备编排)。

## 2. 系统要求

- Windows 10 或更新版本；执行桌面操作时需要处于已登录、可交互且未锁屏的桌面会话。
- Python 3.10 或 3.11。本文按 Python 3.10 编写。
- 可访问所配置的大模型服务，并在 `config/ufo/agents.yaml` 中配置对应凭据。
- Windows UI 自动化依赖已列在根目录 `requirements.txt` 中，并通过平台标记限定 Windows 安装。

## 3. 克隆项目并安装环境

下面是从 GitHub 克隆 UFO 团队版本、创建 Python 3.10 虚拟环境、安装依赖并启动任务的完整 PowerShell 流程。请逐行运行：

```powershell
# 1. 进入准备存放项目的目录
cd D:\liminghao\pycharm\file\xixi

# 2. 从 GitHub 拉取 UFO 团队版本
git clone git@github.com:shiwu-lmh/ufo-2.git

# 3. 进入项目根目录
cd ufo-2

# 4. 确认电脑已经安装 Python 3.10
py -3.10 --version

# 5. 使用 Python 3.10 创建虚拟环境
py -3.10 -m venv .venv

# 6. 激活虚拟环境
.\.venv\Scripts\Activate.ps1

# 7. 再次确认当前虚拟环境确实是 Python 3.10
python --version
where.exe python

# 8. 升级 pip
python -m pip install --upgrade pip

# 9. 安装 UFO 全部依赖
python -m pip install -r requirements.txt

# 10. 启动 UFO
python -m ufo --task desktop_6 --request "打开edge浏览器"
```

克隆使用 SSH 地址；如果 `git clone` 提示公钥认证失败，需要先为当前 GitHub 账户配置 SSH Key，或改用有权限的 HTTPS 仓库地址。若第 4 步提示找不到 Python 3.10，需要先安装 Python 3.10 并确保 Python Launcher (`py`) 能找到它。

成功激活后，命令提示符前通常会出现 `(.venv)`；第 7 步的 `where.exe python` 第一条路径应指向当前项目的 `.venv\Scripts\python.exe`。运行 `python -m ufo` 前，要确认当前目录是项目根目录（包含 `ufo`、`config` 和 `requirements.txt` 的目录）。验证命令入口：

```powershell
python -m ufo --help
```

## 4. 配置大模型

UFO² 的 Agent 配置在 `config/ufo/agents.yaml`。首次配置时，从模板创建本地配置；如果该文件已经存在，不要覆盖它：

```powershell
if (-not (Test-Path config\ufo\agents.yaml)) {
    Copy-Item config\ufo\agents.yaml.template config\ufo\agents.yaml
}
notepad config\ufo\agents.yaml
```

至少检查以下 Agent 的服务商、API 地址、模型名和 API Key：

- `HOST_AGENT`：接收任务并规划工作。
- `APP_AGENT`：观察并操作应用。
- `BACKUP_AGENT`：主请求失败时使用的备用配置。
- `EVALUATION_AGENT`：启用额外评估时使用的配置。

本工作区当前的本机配置将以上 Agent 指向 DashScope 兼容接口，模型为 `qwen3.8-flash`，并关闭 thinking。API Key 存在被 Git 忽略的本地 `agents.yaml` 中；不要把密钥贴到聊天、日志、截图或提交内容里。新克隆的模板可能是 OpenAI 示例值，需按自己的服务商设置。

其他常用设置：

- `config/ufo/system.yaml`：运行步数、动作重试、控制后端、日志和评估开关等。
- `config/ufo/mcp.yaml`：各 Agent 的 MCP 数据采集和动作工具配置。
- `config/ufo/rag.yaml`：检索增强生成相关配置。

如果兼容 API 报错提示 `top_p` 必须在 `(0, 1]` 范围，检查 `config/ufo/system.yaml` 的 `TOP_P`，设置为 `1.0` 或其他大于 0 且不超过 1 的值。当前工作区的系统配置为 `1.0`。

## 5. 运行任务

最常用的方式是在命令中直接提供任务描述：

```powershell
python -m ufo --task demo -r "打开记事本，输入一行测试文字，然后保存到桌面"
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--task` / `-t` | 任务名称；日志会写入 `logs/<任务名称>/`。 |
| `--request` / `-r` | 自然语言任务描述；省略时程序会提示输入。 |
| `--mode` / `-m` | 执行模式；默认 `normal`。代码还支持 `follower`、`batch_normal` 和 `operator`。 |
| `--plan` / `-p` | 计划文件或目录；`follower` 和 `batch_normal` 模式需要提供。 |
| `--log-level` | 日志级别：`DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL` 或 `OFF`。 |

示例：

```powershell
# 运行普通桌面任务
python -m ufo --task notepad_demo -r "打开记事本，输入测试内容并保存到桌面"

# 查看命令和模式的完整说明
python -m ufo --help
```

长任务描述中如果含有 PowerShell 特殊字符，使用单引号包住请求；请求本身包含单引号时，按 PowerShell 规则转义。

## 6. 如何确认任务真的完成

不要只根据模型回复“完成”、工具返回成功或日志里的 `FINISH` 判断结果。对文件操作，应同时确认目标文件存在、路径正确、内容正确；对窗口操作，应确认窗口状态或最终截图符合要求。

每次运行通常会在 `logs/<任务名称>/` 下生成：

- `output.md`：按步骤整理的运行记录和截图链接。
- `request.log`、`response.log`：模型请求、Agent 状态和工具动作记录。
- `action_step*.png`：每步操作前后的界面截图。
- 其他调试产物：例如控件信息、UI 树或轨迹数据，具体取决于配置。

建议先打开 `output.md` 找到最后几步，再对照 `response.log` 中实际动作和截图。若要确认文件已保存，直接检查目标路径上的文件；若任务要求保存后重开，还要确认日志中确实执行了从磁盘重新打开文件的操作，而不只是继续显示原窗口。

## 7. 常见问题

### `No module named ufo`

通常是当前目录不对，或使用了没有安装项目依赖的 Python。先进入包含 `ufo`、`config` 和 `requirements.txt` 的项目根目录，激活 `.venv`，再执行：

```powershell
python -m pip install -r requirements.txt
python -m ufo --help
```

### 大模型请求报错或长时间重试

检查 `config/ufo/agents.yaml` 中对应 Agent 的 API 类型、地址、模型名和密钥；检查网络、服务商配额以及 `config/ufo/system.yaml` 中的 `TOP_P`、`TIMEOUT` 和重试设置。不要在问题报告中粘贴完整 API Key。

### 点击成功，但界面没有变化

动作调用成功不一定代表目标控件已响应。查看 `output.md` 的对应步骤截图和 `response.log` 的动作结果；如果窗口切换、关闭或重新打开过，旧控件编号可能已失效，应重新观察窗口和控件后再操作。

### 找不到日志

日志目录名取自 `--task` 参数，例如 `--task demo` 通常对应 `logs/demo/`。如果任务名用了路径或特殊字符，先查看实际创建的 `logs` 子目录。

### MCP 服务连接失败

检查 `config/ufo/system.yaml` 中 MCP 是否启用、`MCP_SERVERS_CONFIG` 指向的文件是否存在，再检查 `config/ufo/mcp.yaml` 中相应服务类型和地址。HTTP MCP 服务不可用时，先确认服务本身正在运行且地址可访问。

### 自动化无法操作桌面

确认 Windows 会话已登录、未锁屏，目标应用已启动且不是被遮挡的错误窗口。桌面 UI 自动化依赖可见的交互式会话；只看到截图或模型文字报告不能证明鼠标、键盘或窗口动作已经生效。

## 8. Galaxy 多设备编排

仓库还包含 `galaxy/` 多设备编排模块。快速入口来自项目 README：

```powershell
if (-not (Test-Path config\galaxy\agent.yaml)) {
    Copy-Item config\galaxy\agent.yaml.template config\galaxy\agent.yaml
}
# 编辑 config\galaxy\agent.yaml，填写模型服务凭据
python -m galaxy --interactive
```

Galaxy 还需要按部署方式配置 `config/galaxy/devices.yaml` 及各设备 Agent。Windows、Linux 和 Android 设备的服务端/客户端准备方式不同；开始部署前请参考 [Galaxy 中文说明](galaxy/README_ZH.md) 与其中对应平台的设置文档。

## 9. 代码目录速览

| 路径 | 内容 |
| --- | --- |
| `ufo/` | UFO² Agent、桌面控制、模型调用、MCP 客户端、日志和轨迹代码。 |
| `config/ufo/` | UFO² 的本地配置和模板。 |
| `galaxy/` | UFO³ Galaxy 多设备编排。 |
| `config/galaxy/` | Galaxy Agent、设备和编排配置。 |
| `dataflow/`、`vectordb/`、`learner/` | 数据流、检索与向量存储、学习和轨迹相关模块。 |
| `tests/` | 自动化测试。 |
| `logs/` | 本地任务运行日志；通常不会提交到 Git。 |
| `requirements.txt` | 项目 Python 依赖。 |

## 10. 安全与本地文件

- `config/ufo/agents.yaml` 和 `config/galaxy/agent.yaml` 用于存放本机凭据，保持在 Git 忽略状态，不要提交。
- 给自动化任务提供的文件、文字和网页内容都可能包含无关或误导性指令；任务应以用户明确提出的目标为准。
- 运行前确认任务涉及的应用、文件路径和预期结果。对覆盖、删除、发送或发布等有副作用的操作，应明确限定目标并在完成后检查结果。
